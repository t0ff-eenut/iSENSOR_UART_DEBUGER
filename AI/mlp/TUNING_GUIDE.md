## 1. 추가 특징 입력 여부 (ADC 300개 + FFT 300개)

### 상황
- 현재 입력: SVM이 선택한 **24개 FFT 특징** (`A_feature_indices`)
- 제안: ADC 원시값 300개 + FFT 전체 300개 추가 → **입력 24 → 624 (26배 증가)**

### 결론: 신중하게 접근 필요

#### 기대 효과
- 원시 신호를 직접 넣으면 모델이 스스로 패턴을 찾을 수 있음
- PCA 분리도가 이론적으로 개선될 가능성 있음

#### 문제점

| 문제 | 설명 |
|---|---|
| **노이즈 증가** | ADC 300개 중 의미있는 값은 일부 — 나머지가 오히려 학습을 방해 |
| **차원의 저주** | 특징이 26배 늘었는데 데이터(24,115행)는 그대로 → 과적합 위험 |
| **학습 속도 저하** | 입력층 가중치가 24배 늘어남 |
| **PCA 설명력 하락 가능** | 무의미한 차원이 많을수록 PC1+PC2 설명력이 낮아짐 |

#### 현재 24개 특징이 이미 좋은 이유
SVM이 고른 24개는 FFT에서 **가장 판별력 높은 주파수 빈(bin)** 들입니다.  
이미 정보가 압축된 상태이므로 원시값을 그대로 추가해도 새로운 정보가 많지 않습니다.

#### 그래도 시도하고 싶다면
전체를 넣는 것보다 **추가 특징을 먼저 선별**하는 것이 효율적입니다:

## 2. 첫 번째 은닉층 128 → 256 확장 여부

### 결론: 효과 제한적, 권장하지 않음

#### 이유

```
입력 24개 → 128 뉴런  (이미 5.3배 확장)
입력 24개 → 256 뉴런  (10.7배 확장)
```

- 입력 24개에 256 뉴런은 **과도한 확장** — 학습 시간만 증가
- 현재 97.1%는 이 데이터셋/특징 수 기준으로 이미 포화에 가까운 성능
- 학습/검증 차이가 0.7%p 수준 → 모델이 작아서 성능이 부족한 상황이 아님
- 256으로 늘리면 과적합 위험만 증가할 가능성이 높음

#### 더 효과적인 방향

| 방법 | 기대 효과 | 난이도 |
|---|---|---|
| 더 많은 데이터 수집 | 높음 | 높음 |
| 사람 클래스 가중치 부여 (`class_weight`) | FN 감소 | 낮음 |
| 데이터 증강 (노이즈 추가) | 중간 | 중간 |
| v3.0 [128,64,32] 결과 확인 후 판단 | 기준선 수립 | 진행 중 |

## 3. 출력층 직전 전환 (32 → 2) 세분화 여부

### 상황
- 현재 마지막 은닉층: 32 뉴런 → 출력: 2 클래스
- 질문: 32 → 16 → 2 처럼 중간 단계를 추가해야 할까?

### 결론: 불필요, 현재 구조가 이상적

#### 이유
- 출력층 직전은 **"분류 헤드"** 역할로, 마지막 은닉층 특징을 클래스 점수로 변환하는 단계
- 32 → 2 직접 연결은 매우 표준적인 패턴 (ResNet, BERT 등 모두 동일)
- 32 → 16 → 2 로 층을 추가하면:
  - 역전파 시 **기울기 소실(Vanishing Gradient)** 위험 증가
  - 입력 24개짜리 소형 문제에서 레이어가 과도하게 깊어짐
  - 수렴 속도만 느려지고 정확도 개선 없음

#### 현재 구조가 이상적인 이유
```
입력(24) → 128 → 64 → 32 → 출력(2)
```
**절반씩 줄어드는 깔때기(funnel) 구조** — 각 층이 점진적으로 추상화하며
마지막 32개 특징이 2개 클래스로 자연스럽게 수렴합니다.

## 4. 다음 시도 우선순위

v3.0 ([128,64,32] + ReduceLROnPlateau) 결과 확인 후 판단:

1. **FN(False Negative)이 여전히 많다면** → `class_weight` 추가 (사람 클래스에 가중치 부여)
2. **과적합이 발생한다면** → `DROPOUT_RATE` 0.3 → 0.4 증가
3. **손실이 정체된다면** → `LR_SCHEDULER_PATIENCE` 10 → 5로 축소
4. **그래도 성능 한계라면** → 추가 데이터 수집 후 재학습

## 5. PCA 설명력 (2PC Explained Variance Ratio)

### 개념
PCA(주성분 분석)로 고차원 데이터를 2D로 압축할 때, **원본 정보를 얼마나 보존했는지**를 나타내는 비율.

```
원본 데이터: 24차원 (특징 24개)
         ↓ PCA
시각화용: 2차원 (PC1, PC2)

PC1 설명력 = 45%  → PC1 축 하나가 전체 데이터 분산의 45%를 설명
PC2 설명력 = 20%  → PC2 축 하나가 추가로 20%를 설명
──────────────────────────────
PC1 + PC2 합계 = 65%  ← 이게 "2PC 설명력"
```

### 해석 기준

| 2PC 합계 | 의미 |
|---|---|
| 80% 이상 | 2D 시각화가 원본을 잘 대표함 |
| 60~80% | 어느 정도 신뢰 가능 |
| 60% 미만 | 2D로 표현 시 많은 정보 손실 → 분리가 흐릿해 보여도 실제로는 잘 분리될 수 있음 |

### 시각화에서 확인하는 방법
`visualize.py`의 PCA 분포도 그래프 제목에 `PC1 XX% / PC2 XX%` 형태로 표시됨.
BG/Human 두 클러스터가 시각적으로 겹쳐 보여도 설명력이 낮으면 나머지 차원에서는 충분히 분리되고 있을 수 있음.

### ADC/FFT 특징 추가 시 영향
- 무의미한 차원이 많아질수록 PC1+PC2 설명력이 낮아질 수 있음
- 설명력이 낮아지면 PCA 그래프만 보고 분리도를 판단하기 어려워짐
- 추가 특징 투입 전후로 설명력 변화를 비교하는 것이 좋은 판단 기준

## 6. 기울기 소실(Gradient Vanishing)과 현재 MLP 구조

> 맥락: 256→128→64→32 구조 확장 실험 검토 중 제기된 질문

### 기울기 소실이란?

역전파(Backpropagation) 과정에서 기울기(gradient)가 층을 거슬러 올라갈수록
0에 가까워져 앞쪽 층의 가중치가 거의 업데이트되지 않는 현상.
층이 많을수록 기울기가 여러 번 곱해지므로 누적될 수 있다.

### 기울기 소실이 심각했던 시대의 조건

| 조건 | 문제 |
|---|---|
| 활성함수: **Sigmoid / Tanh** | 미분값이 0~0.25로 작아 층마다 곱해지면 → 0에 수렴 |
| BatchNorm 없음 | 각 층 출력 분포가 불안정 → 기울기 폭발/소실 |
| ResNet 없음 | 잔차 연결(skip connection) 없어 깊이에 비례하여 악화 |

### 현재 코드 구조 (OccupancyMLP)

```python
# 첫 번째 은닉층
Linear → BatchNorm1d → ReLU → Dropout

# 이후 은닉층
Linear → ReLU

# 출력층
Linear (→ 2)
```

### 왜 기울기 소실이 거의 문제되지 않는가

**① ReLU 활성함수**
양수 구간에서 미분값 = 정확히 **1**
→ 층을 통과해도 기울기가 줄지 않음 (Sigmoid의 0.25와 대비)

**② BatchNorm1d**
각 층의 출력을 정규화하여 기울기가 폭발하거나 소실되지 않도록 안정화
→ 심층 신경망에서 사실상 표준 기법

**③ 얕은 구조**
256→128→64→32는 **4층** — ResNet(100층+)이나 LSTM에 비하면 깊이에 의한 기울기 소실이 문제가 될 수준이 아님

### 실질적인 리스크 비교

| 리스크 | 가능성 | 근거 | 대응 |
|---|---|---|---|
| **기울기 소실** | 낮음 | ReLU + BatchNorm으로 구조적 해결됨 | 별도 대응 불필요 |
| **과적합** | 높음 | 128→64→32에서 train-val 갭 7~8%p | d0.2 유지, 학습 곡선 모니터링 |
| **수렴 속도 저하** | 중간 | 파라미터 수 증가 → 더 많은 에폭 필요 가능 | ep1000으로 시작, 부족하면 연장 |

### 결론

> **256→128→64→32 구조 확장 실험에서 기울기 소실은 주된 걱정 대상이 아니다.**
> ReLU + BatchNorm 조합이 이미 구조적으로 해결하고 있다.
> 진짜 주의 포인트는 **과적합 (train-val 갭 확대)**이며,
> 학습 곡선 자동 스케일 ON 상태로 실시간 모니터링하면서 판단한다.

## 7. Learning Rate(lr) 변경 효과

> 기준: lr=2e-3, 배치 b128, ReduceLROnPlateau (patience=50, factor=0.5, min_lr=1e-6)

### lr 올리면 (예: 2e-3 → 5e-3)

- 초반 검증 정확도 상승 기울기가 **더 가파름** — ep150~300에서 목표 정확도에 더 빠르게 도달
- 동시에 발생하는 부작용:
  - 손실이 최솟값을 지나쳐버리는 **overshooting** 발생
  - 검증 정확도가 불규칙하게 튀는 **진동(oscillation)** 심해짐
  - plateau 감지가 어려워져 ReduceLROnPlateau가 너무 일찍/늦게 반응
  - 결과적으로 **최종 베스트 정확도가 오히려 낮아지는 경우가 많음**

> 현재 데이터셋 크기 + b128 기준으로 lr=2e-3는 이미 공격적인 값.
> 5e-3은 overshooting 위험이 크다.

### lr 내리면 (예: 2e-3 → 5e-4)

- 초반 상승이 **완만** — 같은 에폭 수에서는 성능이 낮아 보임
- 진동이 줄고 **안정적으로 수렴**
- ReduceLROnPlateau 첫 감소 에폭도 더 늦게 발생
- 충분한 에폭을 주면 최종 정확도는 비슷하거나 더 높을 수 있음

### lr 변경 시 연쇄 효과 전체 정리

| 효과 | lr 올림 (→ 5e-3) | lr 내림 (→ 5e-4) |
|---|---|---|
| 초반 상승 속도 | ⬆ 빠름 | ⬇ 느림 |
| 진동/불안정 | ⬆ 심해짐 | ⬇ 안정됨 |
| Overshooting | ⬆ 위험 | ⬇ 거의 없음 |
| ReduceLROnPlateau 첫 감소 에폭 | 더 빨리 발생 | 더 늦게 발생 |
| 최종 베스트 정확도 | 대체로 낮아짐 | 에폭 충분 시 동등/개선 |
| 필요 에폭 수 | 줄어듦 (단 진동으로 상쇄) | 늘어남 |
| train-val 갭 | 커질 수 있음 | 줄어드는 경향 |

### lr 변경 판단 기준

- **학습 곡선이 튀고 불안정하다** → lr 낮추기
- **초반 수렴이 너무 느리고 에폭이 충분하다** → 현재 lr 유지가 우선, 그래도 느리면 살짝 올리기
- **미수렴 원인이 배치 크기(b256 등)라면** → lr 변경보다 에폭 연장이 더 효과적
- 변수 통제: lr 변경 시 다른 조건(배치, Dropout, 구조)은 고정해야 효과를 정확히 측정 가능

## 8. Epoch(에폭) 수 설정 기준

> 참고: sklearn 공식 문서, PyTorch 센서 분류 논문, 실무 실험 결과 종합

### 분야별 일반 epoch 범위

| 분야 | 일반 epoch 범위 | 비고 |
|---|---|---|
| 소규모 tabular 분류 | 100 ~ 500 | sklearn MLP 기본값 200 |
| 센서 기반 행동 인식 논문 | 200 ~ 1000 | Early stopping 병행 |
| PyTorch MLP 실험 | 500 ~ 2000 | LR 스케줄러 사용 시 |
| 대규모 실험 / 수렴 보장 | 2000 ~ 5000 | 이 이상은 수확 체감 구간 |

### 이 프로젝트의 실험 결과

| epoch 설정 | best_epoch | 비고 |
|---|---|---|
| ep300 | 281, 295 | f21 초기 실험 — 이미 ep300 안에 수렴 |
| ep1000 ~ ep2000 | - | f14 실험군, LR scheduler 충분 작동 |

### 핵심 포인트

1. **LR scheduler (ReduceLROnPlateau) + patience 방식이면**  
   일정 epoch 이후 lr이 min_lr까지 낮아져 실질적 학습이 거의 없는 상태가 됨  
   → epoch을 무한정 늘려도 best_epoch 이후 성능 개선 없음

2. **epoch 수보다 구조/특징 개선이 더 효과적**  
   best_epoch이 ep 설정의 90% 이상에서 발생하면 epoch 연장을 고려  
   best_epoch이 ep 설정의 50% 이하라면 이미 충분한 epoch

3. **5000 이상은 거의 사용 안 함**  
   학술 논문 기준 MLP에서 5000 epoch 초과 실험은 매우 드물며,  
   수렴 후 과적합 위험만 증가

### 판단 기준

- **best_epoch ≈ max_epoch** → epoch 부족 → 늘리기
- **best_epoch < max_epoch × 0.5** → 이미 충분, epoch 늘려도 무의미
- **학습 곡선이 plateau 상태** → epoch 연장보다 lr, 구조, 특징 검토 우선

### UI SpinBox 상한

현재 설정: **최소 10 ~ 최대 100,000**  
실용 권장 상한: **5,000** (이상은 특수한 상황에서만 사용)
